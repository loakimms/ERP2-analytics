ERP2 Analytics는 광고 성과, 쇼핑 순위, 구매 키워드, 리뷰, Q&A, AI 분석을 한 DB와 한 운영 스택으로 묶은 분석 전용 시스템입니다. 데이터 규모상 광고 검색어, 쇼핑 순위, GFA, 광고 소재가 핵심 대용량 fact 축이며, 구매 키워드와 리뷰/Q&A가 상품 운영 판단과 AI 분석의 품질 데이터를 보강합니다.

9. 리스크와 개선 우선순위

1순위: 구매 키워드 CDP 로그인 안정성 - 해결 완료

구매 키워드는 처음부터 Commerce 로그인 URL로 시작하도록 개선했고, Host Agent 버전/관리번호도 올려 설치본 업데이트가 감지되도록 했다.

2순위: CDP 이벤트 장기 추적 - 개선 완료

Collector 완료 시 collector_diagnostics를 detail_json과 collection_job_event.detail_json에 남겨 stage/category/sample error를 구조화한다.

3순위: 대용량 fact 조회 최적화 - 개선 완료

naver_ad_searchword_daily, naver_ad_creative_daily, naver_product_rank_daily, tracked_product_rank_daily에 날짜·상품·캠페인·키워드·source 기준 복합 인덱스를 추가했다.

운영 안정성: lock 기반 배포 유지

Web/API는 불변 태그와 /version.json, /api/version으로 검증된다. NAS 배포 시 Host Agent installer release 확인까지 함께 유지해야 한다.

인증과 런타임 산출물

  • NAS 운영은 Firebase ID token 기반 인증을 사용하며, 민감 route는 role/level 검사를 거친다.
  • API/AI 설정은 DB 저장을 기준으로 하며, lock 파일에는 secret을 넣지 않는다.
  • Docker image는 analytics-analytics-api:<tag>, analytics-analytics-web:<tag> 형식이다.
  • Host Agent 상태는 %LOCALAPPDATA%\ERP2-Analytics-HostChrome\collector-background.*.json에 기록된다.
  • AI 분석 결과는 analysis_run, analysis_blob, trace 계열 테이블에 저장된다.

11. 결론

ERP2 Analytics는 단순 리포팅 화면이 아니라, 공식 API·CDP·수동 업로드·AI 분석을 통합한 운영형 데이터 플랫폼이다. 현재 저장 데이터 기준으로 광고 검색어, GFA, 쇼핑 순위, 광고 소재가 대용량 분석 축을 형성하고 있으며, 구매 키워드·리뷰·Q&A가 상품 운영 판단을 보강한다.

현 시점의 가장 큰 운영 개선 지점은 구매 키워드 CDP 수집의 로그인 안정성이다. 이 부분을 새 Host Agent 기준으로 검증하면 광고/검색/구매/리뷰/Q&A 데이터가 하나의 안정된 상품 운영 분석 흐름으로 연결된다.
