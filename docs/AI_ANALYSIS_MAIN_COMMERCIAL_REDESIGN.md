# AI 분석 메인 상용화 재설계안

## 1. 목적

이 문서는 현재 `ERP2-analytics`의 `AI 분석` 메인을 다음 수준으로 재설계하기 위한 기준 문서다.

- 단순 분석 화면 모음이 아니라, 실제 운영자가 매일 사용하는 `분석 -> 판단 -> 행동 -> 검증` 엔진으로 전환한다.
- 기존 문서에서 빠져 있던 `리뷰 Q&A`, `판매 분석` 영역까지 포함해 제품별 최종 판단이 가능하도록 확장한다.
- 내부 도구 수준을 넘어, 향후 유료 분석 서비스로 제공 가능한 수준의 구조, 설명 가능성, 운영 안정성을 확보한다.

핵심 목표는 하나다.

`광고`, `오가닉`, `구매`, `판매`, `리뷰`, `Q&A`, `수요/트렌드`를 제품 단위로 묶어
`지금 문제점이 무엇인지`, `왜 그런지`, `지금 무엇을 해야 하는지`를 우선순위와 근거까지 포함해 제시한다.


## 2. 현재 상태 진단

현재 프로젝트는 데이터가 부족한 상태가 아니라, 데이터는 충분히 수집되고 있으나 AI 메인에서 그것을 최종 의사결정으로 통합하지 못하고 있는 상태다.

### 2.1 현재 이미 확보된 데이터 축

- 광고 성과: `naver_ad_keyword_daily`, `naver_ad_searchword_daily`, `naver_ad_creative_daily`
- 오가닉/순위: `naver_product_rank_daily`, `tracked_product_rank_daily`, `tracked_product_keyword`, `tracked_product_meta`
- 구매 키워드: `naver_smartstore_purchase_keyword_daily`
- 판매/매출: `naver_commerce_product_sales_daily`, `naver_commerce_product_order_raw`
- 상품 페이지/상품지수: `tracked_product_page_daily`, `tracked_product_index_*`, `tracked_product_sales_manual`
- 리뷰/VOC: `naver_review_raw`, `naver_product_review_daily`, `review_reply_draft`
- Q&A: `commerce_qna_raw`, `commerce_qna_analysis`, `commerce_qna_analysis_keyword`, `commerce_qna_analysis_issue_tag`
- AI/A-1/Trace: `sku_*_daily`, `gpt_action_daily`, `ai_decision_log`, `analysis_*`

### 2.2 현재 AI 메인의 한계

- 현재 `AI 분석` 메인은 실질적으로 `A. 오가닉 순위 분석`, `A-1 검증`에 집중되어 있다.
- `광고 운영 판단`, `구매·전환 기반 분석`, `수요·트렌드 분석`, `SKU 통합 운영 정책`은 비전 설명 수준이거나 초기 구성 단계다.
- `리뷰 분석`, `Q&A 분석`, `판매 분석`은 별도 메뉴로 존재하지만 AI 메인의 최종 판단 흐름에는 통합되어 있지 않다.
- 결과적으로 현재 구조는 `메뉴별 분석`은 가능하지만, `제품별 최종 행동 판단`은 약하다.


## 3. 재설계 원칙

AI 메인을 다시 설계할 때 반드시 지켜야 할 원칙은 아래와 같다.

### 3.1 질문 중심이 아니라 판단 중심

좋지 않은 구조:

- "이 키워드 어때?"
- "이 상품 괜찮아?"

좋은 구조:

- "이 키워드는 유지/중단/테스트 중 무엇인가?"
- "이 SKU는 확대/방어/개선 우선/축소 중 무엇인가?"
- "이 상품은 광고보다 리뷰 개선이 먼저인가?"

### 3.2 제품 단위 의사결정 우선

광고, 오가닉, 리뷰, Q&A, 판매는 각각 의미가 있지만, 실제 운영은 상품 단위로 이루어진다.

따라서 최상위 엔티티는 다음 순서로 우선한다.

1. `SKU / Product`
2. `Keyword`
3. `Campaign / Adgroup / Creative`

### 3.3 GPT는 자유 대화가 아니라 Decision Engine

GPT는 분석 대화창이 아니라, 정제된 입력을 바탕으로 고정 스키마를 출력하는 판단 엔진으로 사용한다.

- raw 테이블을 직접 GPT에 전달하지 않는다.
- decision mart/view를 만든 뒤 해당 결과만 전달한다.
- 출력은 반드시 구조화 JSON으로 고정한다.

### 3.4 즉시 실행 금지, Action Queue 우선

광고/SEO/운영 판단은 돈과 직결되므로 다음 구조를 기본으로 한다.

`판단 결과 -> Action Queue 적재 -> 운영자 승인 -> 실행 -> 사후 검증`

### 3.5 설명 가능성은 필수

유료 서비스 수준에서는 `왜 이런 판단이 나왔는지`를 보여주지 못하면 신뢰를 얻기 어렵다.

모든 결과는 아래를 함께 가져야 한다.

- 판단 점수
- 근거 지표
- 룰 트리거
- 입력 기간
- 신뢰도
- 추천 액션
- 검증 로그 링크


## 4. AI 메인 재정의

기존 `AI 분석` 메인은 이름만 유지하거나, 아래 중 하나로 변경하는 것을 권장한다.

- `AI 운영 센터`
- `AI 전략 엔진`
- `AI Growth Engine`

가장 무난한 운영형 명칭은 `AI 운영 센터`다.
가장 상업적이고 서비스형 느낌이 강한 명칭은 `AI Growth Engine`이다.

본 문서에서는 상위 개념을 `AI 운영 센터`로 통일한다.


## 5. 새 AI 메인 IA

## 5.1 홈: 오늘의 실행

첫 화면은 분석 리포트가 아니라 `지금 해야 할 일` 중심이어야 한다.

### 목표

- 운영자가 30초 안에 오늘의 위험과 기회를 파악한다.
- 각 항목이 바로 액션 큐 또는 상세 판단 화면으로 연결된다.

### 핵심 카드

- 오늘 중단 후보 광고비
- 오늘 확대 후보 SKU
- 오가닉 급락 방어 필요 SKU
- VOC 위험 SKU
- FAQ/상세 보완 필요 SKU
- 판매 과투입 SKU
- 데이터 신뢰도

### 핵심 출력

- `오늘 바로 줄여야 할 광고`
- `오늘 바로 테스트할 키워드`
- `오늘 광고보다 리뷰 개선이 먼저인 상품`
- `오늘 FAQ/상세 개선이 전환에 더 중요한 상품`


## 5.2 상품별 운영 판단

이 메뉴가 AI 메인의 핵심 허브다.

### 목표

각 상품/SKU에 대해 모든 데이터를 하나의 판단 카드로 통합한다.

### 상품 카드에 들어갈 필수 정보

- 상품명 / SKU / 대표 URL
- 오가닉 건강도
- 광고 효율도
- 판매 성장도
- 리뷰 위험도
- Q&A 전환장벽 점수
- 수요 모멘텀
- 최종 정책 분류
- 이번 주 실행 제안 3개

### 최종 문장 예시

- 광고 확대보다 리뷰 개선이 먼저입니다.
- 오가닉 방어 광고 3일 테스트가 필요합니다.
- 광고를 줄이고 SEO 확장을 우선해야 합니다.
- 판매는 좋지만 VOC 위험이 증가 중이라 확대는 보수적으로 가야 합니다.


## 5.3 광고 운영 판단

광고 운영 판단은 단순 대시보드가 아니라 액션 결정 화면이어야 한다.

### 하위 탭

- 키워드 액션
- 검색어/제외 후보
- 광고-오가닉 잠식
- 예산 재배분
- 소재/지면 판단

### 핵심 질문

- 어떤 키워드를 중단해야 하는가?
- 어떤 키워드를 테스트해야 하는가?
- 어디에 예산을 더 써야 하는가?
- 광고가 순증 매출을 만드는가, 오가닉을 잠식하는가?


## 5.4 판매·전환 판단

기존 문서에서 빠졌지만 반드시 AI 메인에 포함되어야 한다.

### 목표

광고 성과가 아니라 실제 매출과 주문 기준으로 전략을 교정한다.

### 핵심 질문

- 실제로 돈을 만드는 SKU는 무엇인가?
- 광고 효율은 좋아 보여도 실제 매출 기여는 약한가?
- 환불/품질 이슈를 고려하면 확대가 위험한가?
- 상위 매출 SKU에 오가닉/광고/리뷰 정책이 일치하는가?

### 주요 출력

- 매출 성장형 SKU
- 광고 과투입 SKU
- 환불 리스크 SKU
- 카테고리 성장 기회
- 상위 매출 집중 전략


## 5.5 리뷰·VOC 판단

리뷰는 구매 이후 경험 데이터지만, 광고 확대/축소 판단에 직접 반영돼야 한다.

### 목표

전환을 막는 평판 문제와, 확장 가능한 강점을 동시에 포착한다.

### 핵심 질문

- 어떤 상품이 평판 때문에 광고 확대가 위험한가?
- 어떤 이슈 카테고리가 반복되는가?
- 어떤 상품은 리뷰 강점을 활용해 더 확대할 수 있는가?

### 주요 출력

- 부정 비율 급등 상품
- 위험 카테고리별 상위 SKU
- 강점 카테고리 기반 확장 SKU
- 광고 확대 금지 SKU
- 리뷰 개선 후 재광고 대상


## 5.6 Q&A 전환장벽 판단

Q&A는 구매 직전 마찰을 보여주는 데이터로, 판매 전환 개선에 매우 중요하다.

### 목표

고객이 사기 전에 어디서 막히는지 파악하고, 상세페이지/FAQ/답변 정책 개선으로 연결한다.

### 핵심 질문

- 어떤 상품이 구매 직전 문의가 많은가?
- FAQ로 흡수해야 할 반복 질문은 무엇인가?
- 부정 문의가 많은 상품은 무엇인가?
- 광고 확대보다 상세 설명 개선이 먼저인 SKU는 무엇인가?

### 주요 출력

- 구매직전 문의 높은 SKU
- FAQ 후보 상위 SKU
- 부정 문의 상위 SKU
- 답변 정책 보완 우선순위
- 상세페이지 보강 우선순위


## 5.7 수요·트렌드 판단

### 목표

트렌드 데이터로 수요의 방향성을 읽고, 광고/SEO/상품 운영 방향을 교정한다.

### 핵심 질문

- 지금 붙는 키워드는 무엇인가?
- 하락하는 키워드에 예산을 유지할 가치가 있는가?
- 시즌성/이벤트성 상품은 무엇인가?


## 5.8 SKU 통합 운영 정책

이 메뉴는 각 상품의 장기 운영 정책을 확정하는 계층이다.

기존 문서의 4분면 구조를 확장해, 리뷰/Q&A/판매까지 포함한 6분류를 권장한다.

### 권장 정책 분류

- 오가닉 주력형
- 광고 성장형
- 광고 방어형
- VOC 개선 우선형
- FAQ/상세 보완형
- 축소/정리형


## 5.9 실행 큐

AI 판단 결과가 실제 운영으로 연결되는 허브다.

### 유형

- 광고 중단 대기
- 광고 증액 대기
- 광고 테스트 대기
- 제외 키워드 등록 대기
- FAQ 반영 대기
- 상세페이지 보강 대기
- 리뷰 대응 대기
- SEO 작업 대기


## 5.10 검증/설명 로그

현재 A-1 Trace 철학을 전체 AI 메인으로 확장해야 한다.

### 반드시 보여줘야 하는 것

- 입력 기간
- 입력 데이터 요약
- 주요 지표
- 룰 트리거
- GPT 판단 결과
- 운영자 승인/수정 이력
- 7일 후 성과


## 6. 포함되어야 할 판단 축

상용화 수준에서는 아래 7축을 모두 포함해야 한다.

### 6.1 오가닉 축

- 순위 추이
- 변동성
- 커버리지
- 신규 진입/급락/방어 필요

### 6.2 광고 축

- 키워드 유지/중단/테스트
- 검색어 품질
- 소재/지면 성과
- 예산 탄력성
- 잠식 여부

### 6.3 구매 축

- 이미 사는 키워드
- 미집행 광고 기회
- SKU별 핵심 구매 키워드 구조

### 6.4 판매 축

- 총매출 / 주문수 / 수량
- 상위 상품
- 카테고리 기여
- 환불 영향
- 데이터 커버리지

### 6.5 리뷰 축

- 평점
- 리뷰량 증가율
- 긍정/부정 비율
- 위험 카테고리
- 실행 제안

### 6.6 Q&A 축

- 구매직전 문의
- FAQ 후보
- 부정 문의
- 전환 장벽
- 행동 가이드

### 6.7 수요/트렌드 축

- 검색량 방향
- 키워드 lifecycle
- 시즌/이벤트 민감도


## 7. AI 메인의 최종 질문 구조

새 AI 메인은 데이터를 보여주는 것이 아니라 아래 질문에 답해야 한다.

### 상품 단위

- 이 상품의 가장 큰 문제는 무엇인가?
- 이 상품은 지금 광고를 더 해야 하는가, 줄여야 하는가?
- 이 상품은 광고보다 리뷰/Q&A/상세 개선이 더 시급한가?
- 이 상품은 오가닉 방어가 필요한가?
- 이 상품의 이번 주 최우선 액션 3개는 무엇인가?

### 키워드 단위

- 유지/중단/테스트 중 무엇인가?
- 잠식형인가 순증형인가?
- SEO 확장 대상인가?

### 운영 단위

- 오늘 어떤 액션을 승인해야 하는가?
- 지난주 어떤 판단이 맞았고 틀렸는가?


## 8. 데이터 레이어 재설계

상용화 수준에서는 raw 데이터를 바로 해석하는 구조를 버리고 decision mart 중심으로 재구성해야 한다.

### 8.1 레이어 구조

1. Raw Layer
2. Feature / Mart Layer
3. Decision Layer
4. Action Layer
5. Evaluation Layer

### 8.2 Raw Layer

기존 일별 적재 테이블을 유지한다.

- 광고 raw
- 오가닉 raw
- 구매 raw
- 판매 raw
- 리뷰 raw
- Q&A raw

### 8.3 Feature / Mart Layer

AI 입력을 위한 전처리 계층이다.

권장 mart/view:

- `decision_keyword_daily`
- `decision_sku_daily`
- `decision_campaign_daily`
- `decision_sales_daily`
- `decision_review_daily`
- `decision_qna_daily`
- `decision_product_health_daily`

### 8.4 핵심 통합 mart

가장 중요한 mart는 `decision_product_health_daily`다.

이 테이블은 상품/SKU 단위 최종 판단의 진실원이 된다.

#### 권장 컬럼 예시

- date
- sku_id
- product_url
- product_id_catalog
- product_name
- organic_strength_score
- ad_efficiency_score
- sales_growth_score
- review_risk_score
- qna_barrier_score
- trend_momentum_score
- final_priority_score
- policy_type
- top_issue
- top_action_json
- confidence_score
- data_quality_score


## 9. 리뷰/Q&A/판매 포함 통합 점수 프레임

기존 문서는 광고/오가닉 중심이라 정책 분류가 다소 좁다.
상용화 관점에서는 아래 점수 체계를 권장한다.

### 9.1 오가닉 건강도

구성 요소:

- 상위 노출 키워드 수
- 평균 순위
- 순위 변동성
- 급락 이벤트

### 9.2 광고 효율도

구성 요소:

- ROAS
- CVR
- CPA
- 예산 탄력성
- 잠식 여부

### 9.3 판매 성장도

구성 요소:

- 매출 증감률
- 주문수 증감률
- 상위 상품 유지력
- 환불 영향

### 9.4 리뷰 위험도

구성 요소:

- 평균 평점
- 평점 변화율
- 부정 리뷰 비율
- 위험 카테고리

### 9.5 Q&A 장벽도

구성 요소:

- 구매 직전 문의 수
- 미답변 비율
- 부정 문의 수
- FAQ 후보 비율

### 9.6 수요 모멘텀

구성 요소:

- 검색량 추세
- 라이프사이클 단계
- 계절성 민감도

### 9.7 최종 우선순위 점수

최종 우선순위는 단일 점수로 합산하되, 반드시 하위 점수와 함께 보여준다.

예시:

- `Priority = Opportunity - Risk + Urgency - DataPenalty`

단, 실제 운영에서는 점수 하나만 보여주기보다,
점수 + 이유 + 우선 액션 3개 조합으로 보여주는 것이 안전하다.


## 10. 정책 분류 체계

기존 4분면을 상용형 6분류로 확장한다.

### 10.1 오가닉 주력형

- 오가닉 강도 높음
- 광고 의존도 낮음
- 리뷰/Q&A 리스크 낮음

정책:

- 광고는 방어 범위로 최소 유지
- SEO와 상품 콘텐츠 확장
- 강점 키워드 점유율 확대

### 10.2 광고 성장형

- 광고 효율도 높음
- 판매 성장도 양호
- 수요 상승 시그널 존재

정책:

- 테스트에서 확장으로 이동
- 신규 키워드/소재 확장
- 예산 증액 우선

### 10.3 광고 방어형

- 오가닉 중요 키워드가 흔들림
- 경쟁이 심함
- 매출 안정에 광고 방어 필요

정책:

- 핵심 키워드만 방어
- 기간 제한형 방어 광고
- CTR/소재 품질 유지

### 10.4 VOC 개선 우선형

- 리뷰 위험 높음
- 부정 카테고리 반복

정책:

- 광고 확대 보류
- 리뷰 이슈 해결 후 재확대
- CS/상품 개선 액션 우선

### 10.5 FAQ/상세 보완형

- Q&A 장벽 높음
- FAQ 후보 다수
- 구매 직전 문의 많음

정책:

- 상세페이지 보강
- FAQ 생성
- 답변 템플릿 정비

### 10.6 축소/정리형

- 오가닉/광고/판매 모두 약함
- VOC/Q&A 개선 여지도 낮음

정책:

- 광고 최소화
- 상품 경쟁력 재점검
- 재테스트 전 관찰

## 13. 유료 서비스 수준에서 반드시 추가할 것

내부 도구와 유료 서비스의 차이는 기능 수가 아니라 운영 구조다.

### 13.1 고객별 정책팩

각 고객은 다른 운영 성향을 가진다.

- 보수형
- 공격형
- 효율 최적화형
- 브랜드 방어형
- 매출 확대형

따라서 임계값과 판단 기준은 고객별 `Policy Pack`으로 관리해야 한다.

### 13.2 멀티테넌트

유료 서비스 전환을 고려하면 최소한 아래 구조가 필요하다.

- tenant
- workspace/account
- user/role
- data ownership
- policy ownership
- prompt ownership

### 13.3 데이터 신뢰도 표기

모든 결과에는 `이 판단이 얼마나 믿을 만한지`가 함께 표기되어야 한다.

예시:

- 광고 데이터 최신성
- 판매 커버리지
- 리뷰 분석 커버리지
- Q&A 분석 커버리지
- 오가닉 수집 커버리지

### 13.4 리포트와 실행 분리

유료 서비스에서는 고객에게 보여주는 리포트와 실제 운영 실행 화면을 분리하는 것이 좋다.

- 리포트형: 경영진/고객용
- 실행형: 운영자용

## 16. 이 재설계안의 한 줄 정의

이 시스템은 더 이상 `분석 화면 모음`이 아니다.

`광고, 오가닉, 판매, 리뷰, Q&A, 수요 데이터를 통합해 제품별 문제를 진단하고, 지금 해야 할 행동을 근거와 우선순위까지 제시하는 상업형 AI 운영 판단 엔진`이다.


## 17. 다음 단계 권장 작업

이 문서를 기준으로 바로 이어서 해야 할 작업은 아래 순서가 가장 좋다.

1. `AI 운영 센터` 메뉴 IA를 실제 라우팅 구조로 확정
2. `decision_product_health_daily` 포함 핵심 mart 설계
3. 1차 MVP용 Prompt Spec 파일 정의
4. Action Queue / Decision Log 스키마 확정
5. 홈 화면과 상품별 운영 판단 화면부터 구현

이 5단계를 완료하면, 현재 프로젝트는 내부 분석 도구를 넘어 유료 서비스 수준의 운영 판단 제품으로 발전할 수 있다.
