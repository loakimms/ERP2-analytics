# 1단계(크롬 CDP 창 띄우기) 스크립트+웹 UI 처리 가능성 분석

## 현재 흐름 요약

| 단계 | 담당 | 방식 |
|------|------|------|
| 1. CDP 창 띄우기 | **사용자 + Cursor/PowerShell** | `pwsh -File "C:\dev\ERP2-analytics\tools\collect-via-modal.ps1"` (또는 `start-host-chrome.ps1`) 수동 실행 |
| 2. 네이버 로그인 | 사용자 | CDP 전용 창에서 수동 |
| 3. 호스트 크롬에서 상품 페이지 열기 | **웹 UI** | "호스트 크롬에서 상품 페이지 열기(세션)" 버튼 → API 호출 + `window.open` |
| 4. 수집 실행 | **웹 UI** | "지금 수집" 버튼 → API 호출 |

1단계만 터미널 수동 실행이고, 2~4는 이미 웹/사용자 조합으로 처리되고 있음.

---

## 결론: “웹 버튼 클릭만으로” 1단계 실행은 불가, “스크립트 + UI” 조합으로는 가능

### 왜 “버튼 클릭만”으로는 불가능한가

- **브라우저 보안**: 웹 페이지(JavaScript)는 사용자 PC에서 **임의 프로세스를 띄우거나 로컬 파일을 실행할 수 없음**.
- 따라서 “Analytics 웹에서 버튼 하나로 Chrome CDP 프로세스가 로컬에서 실행된다”는 식의 **순수 웹 전용 해결은 불가능**합니다.

### “스크립트 + 웹 UI”로 할 수 있는 것

1단계를 **완전 자동**으로는 못 하지만, 아래처럼 **스크립트를 유지한 채 UI로 진입 장벽을 낮추는 것**은 가능합니다.

| 방식 | 설명 | 장점 | 단점 |
|------|------|------|------|
| **A. 스크립트 다운로드 + 더블클릭** | 버튼 클릭 시 실행용 `.bat`(또는 단순 `.ps1`) 다운로드 → 사용자가 다운로드한 파일 더블클릭으로 CDP 실행 | 터미널을 열 필요 없음, 구현 단순 | 경로/환경 차이 대응 필요(래퍼에서 경로 설정 또는 안내) |
| **B. Custom URL Protocol** | `erp2-cdp://start` 같은 링크를 웹에 두고, OS에 한 번 등록해 두면 클릭 시 로컬에서 스크립트 실행 | 한 번 등록 후에는 “웹에서 링크 클릭 = CDP 실행”에 가깝게 동작 | 사용자가 프로토콜 등록(레지스트리/설치) 한 번 필요 |
| **C. 로컬 에이전트(트레이/Electron)** | 로컬에 작은 앱이 떠 있고, 웹 또는 로컬 API로 “CDP 시작” 요청 시 앱이 스크립트 실행 | 유연한 제어·상태 표시 가능 | 별도 설치·관리 부담 |

---

## 권장: A(다운로드 + 더블클릭) 먼저 적용

- **목표**: “터미널에 명령 붙여넣기” 대신 **“버튼 클릭 → 파일 받기 → 더블클릭 한 번”**으로 1단계 수행.
- **구현 포인트**:
  1. **웹 UI**
     - 기존 “1. 호스트 크롬(CDP) 전용 창 실행” 영역에  
       **“CDP 실행 스크립트 받기”** 버튼 추가.
     - 클릭 시 `start-host-chrome.ps1`을 실행하는 **래퍼 .bat** (또는 .ps1) 내용을 생성해 다운로드.
       - 예: `ERP2-Analytics-StartCDP.bat`  
         - 내용: `pwsh -NoProfile -ExecutionPolicy Bypass -File "C:\dev\ERP2-analytics\tools\start-host-chrome.ps1"`  
         - 또는 설정/환경에 따라 경로를 바꿀 수 있게 할지 결정.
  2. **경로 이슈**
     - 프로젝트 경로가 사용자마다 다를 수 있음.
     - 선택지:
       - (1) 배포 시점에 서버/빌드에서 `VITE_ERP2_ANALYTICS_TOOLS_PATH` 같은 값을 넣어 고정 경로를 bat에 넣기.
       - (2) “스크립트 받기” 시 사용자에게 **프로젝트 루트 경로** 한 번 입력받아 그 경로를 bat에 넣기.
       - (3) bat는 “현재 사용자 문서/Downloads 아래 고정 폴더”를 기준으로 하고, 실제 `start-host-chrome.ps1`은 그 폴더에 복사해 두는 방식(설치 가이드와 함께 제공).
  3. **기존 “명령 복사”**
     - 터미널을 쓰는 사용자를 위해 “명령 복사”는 그대로 두는 것이 좋음.

이렇게 하면 **1단계는 여전히 “스크립트 실행”**이지만, **실행 방식만 “웹에서 받은 파일 더블클릭”**으로 바꿀 수 있어, “스크립트 + 웹 UI(버튼)”로 처리했다고 볼 수 있습니다.

---

## B(프로토콜 핸들러)를 쓰는 경우

- **목표**: 한 번 등록 후에는 웹에서 “CDP 실행” 링크 클릭만으로 로컬에서 Chrome CDP가 실행되게 함.
- **필요 작업**:
  - Windows에 `erp2-cdp` 프로토콜 등록 (레지스트리 또는 설치 프로그램).
  - 등록 시 “URL 열기” → `pwsh -File "…\start-host-chrome.ps1"` 실행하도록 연결.
- **웹 UI**: “1. 호스트 크롬(CDP) 전용 창 실행”에  
  **“CDP 전용 창 실행(로컬)”** 같은 버튼/링크를 두고, `erp2-cdp://start` 로 이동시키기.
- 사용자 문서(README 등)에 “최초 1회: 프로토콜 등록 방법” 안내 필요.

## 요약

- **1번(크롬 CDP 창 띄우기)을 “웹 버튼 클릭만”으로 브라우저에서 직접 실행하는 것은 보안상 불가능.**
- **스크립트(`start-host-chrome.ps1` / `collect-via-modal.ps1`)는 그대로 두고, 웹 UI로 “실행까지의 경로”를 바꾸는 것은 가능.**
- **현실적인 1단계 개선**:  
  - **A.** 웹에서 “CDP 실행 스크립트 받기” 버튼 → bat/ps1 다운로드 → 사용자가 더블클릭으로 실행.  
  - (선택) **B.** Custom URL Protocol 등록 후, 웹에서 “CDP 실행” 링크 클릭으로 로컬 스크립트 실행.

이렇게 하면 1단계도 “스크립트 + 웹 UI(버튼/링크)”로 처리할 수 있습니다.
